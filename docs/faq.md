# 常见问题

## 听不到声音

**先跑这条命令：**

```powershell
.\.venv\Scripts\python.exe run.py --test-audio
```

它会逐个试听所有输出设备，告诉你声音到底在哪个设备上。

最常见的原因：**默认扬声器是显示器（HDMI / DP 音频）而实际戴着耳机听**。
抓默认扬声器会永远抓不到声音。程序默认会自动探测在出声的设备，
但如果探测结果不对，就用 `run.py --list-devices` 拿 id 填到 `config.yaml` 的 `audio.device`。

也检查一下腾讯会议里扬声器音量有没有到 50% 以上。

## 需要虚拟声卡吗？

**不需要。** 走 WASAPI loopback 直接抓系统输出，也不用开「立体声混音」。

## 共享屏幕时对方能看到这个窗口吗？

看不到。窗口用 `SetWindowDisplayAffinity(WDA_EXCLUDEFROMCAPTURE)` 排除在屏幕捕获之外。

**但一定要自己验证一次**：开着悬浮窗，用腾讯会议「共享屏幕」看一眼对方视角。
别靠「应该没问题」。旧系统上会退回 `WDA_MONITOR`，截到全黑但对方会看到一块黑框。

## 回答区域一直空白 / 没有字

按顺序排查：

1. **确认 `llm.thinking: off`。** 开着思考时思维链会占用 `llm.max_tokens`，
   2000 可能被吃光导致正文为空——HTTP 却是 200，看起来像「调用成功但没回答」。
2. 关掉思考后还有问题，调大 `llm.max_tokens`。
3. 跑 `run.py --ask "随便问一句"` 单独验证接口通不通。

## 第一次提问要等好几秒

冷启动固定开销约 4.2 秒（`import openai` 1.68s + 建客户端 0.74s + DNS/TLS 2.09s）。

程序会在窗口构造时**后台预热**，所以你拖窗口、选设备的时候它已经热好了。
预热后首字从 3.27s 降到 0.62s。

如果预热还没跑完你就抢着提问，会感觉到那几秒。

## 点「提问」没反应

看状态栏——所有反馈都在那里，字比较小容易被忽略。

- 输入框空着按回车 → 提示「先输入要问的内容」
- 生成中 → 回答区会先显示「正在生成…」

## 按住说话没反应

| 提示 | 原因 |
|---|---|
| 按住别放，说完再松开 | 按住时间短于 0.3 秒 |
| 稍等一下 | 上一次识别还没结束 |
| 打开麦克风失败 | 麦克风被别的程序占了，或在设置里换一个麦克风设备 |

「按住说话」录的是**麦克风**，和「开始监听」采的 loopback 是两回事，
所以面试官的声音不会被录进来。

## 面试官的话被当成我提的问题了

麦克风收到了扬声器的声音。**戴耳机**，或把系统音量降低。

## 能用在别的会议软件吗？

能。它抓的是**系统输出**，不关心是哪个软件在出声——
腾讯会议、飞书、钉钉、Zoom 都一样。

## 一定要联网吗？

- **大模型必须联网**（或者你自建了本地兼容接口）。
- **识别可以不联网**：`asr.provider` 设成 `local`，用本地 whisper 完全离线。

## 我的简历和 API Key 安全吗？

`config.yaml` 已被 `.gitignore` 忽略，不会提交到仓库。
设置页的截图（含简历）也被忽略。

简历和最近的问答会作为上下文发给**你自己配置的大模型接口**；
语音识别如果选了讯飞，语音会上传到**讯飞服务器**。介意就切本地 whisper。

## 可以换别的模型 / 网关吗？

可以。改 `config.yaml` 的 `llm.base_url` 和 `llm.model`，
任何 OpenAI 兼容接口都能接。

如果对方也拦 SDK 的 `User-Agent`，改 `app/llm.py` 里的 `USER_AGENT` 常量。

## 支持 macOS / Linux 吗？

**不支持。** 采集靠 WASAPI loopback，防截屏靠 Win32 API，两者都没有跨平台替代方案。

## 回答像通用套话

**填简历。** 这是提升幅度最大的一项：

> 不填：「先看监控大盘，快速判断是全局还是局部问题……」
>
> 填了：「我做过最有挑战的是支付网关重构，把下单 P99 从 1.2 秒降到了 300 毫秒……」

再填上目标岗位 JD，回答会更对准重点。
