# 已知限制

用之前先知道这些边界，比出了问题再找原因省事。

## 平台

- **Windows only。** 依赖 WASAPI loopback 采集和 Win32 防截屏 API。
- 防截屏需要 **Windows 10 2004+**。在旧系统上会退回 `WDA_MONITOR`
  （截到全黑，但**对方会看到一块黑框**）。
- 部分开启硬件加速的**独占全屏**程序可能绕过防截屏限制。

## 延迟

| 场景 | 延迟 |
|---|---|
| 讯飞云端引擎 | 识别约 **20x 实时**（26 秒音频 1.2 秒出结果），端到端主要是 0.6 秒断句等待 |
| 本地 whisper `small`（无独显） | 约 **1.5~3 秒**（含 0.6 秒断句等待） |
| 本地 whisper `base` | 约 **1 秒** |
| 大模型首字 | 预热后约 0.6 秒，未预热约 3.3 秒 |

## 隐私与费用

- 讯飞引擎需要联网，**面试语音会上传到讯飞服务器**；介意隐私就用本地 whisper。
- 讯飞免费额度用尽后需要自行充值。
- 讯飞单次会话上限 60 秒，所以 `audio.max_speech_ms` 不要超过 58000。
  「按住说话」一次最长 30 秒（`voice_input.MAX_SECONDS`），超了自动停。
- 本地 whisper 首次使用需要下载模型（`small` 约 484MB）。

## 音频串音

麦克风和扬声器如果互相串音，**你自己的声音可能被误识别**。用耳机可以彻底避免。

对「按住说话」同理：外放时麦克风会连面试官的声音一起收进去。

## 引擎共用

「按住说话」用的是**同一个识别引擎**（讯飞或本地 whisper）。选本地 whisper 时，
它复用「开始监听」那一份模型，不会额外占内存；但如果还没下载过模型，
第一次按住说话会先触发下载。

## 功能边界

- **截图提问需要多模态模型。** `deepseek-flash` 已验证可用；
  `deepseek-chat` 等纯文本模型会由接口直接返回不支持图片的错误。
- **全局快捷键依赖 `keyboard` 包**，装不上不影响主流程，只是没有全局热键。
- **本地 whisper 的中文标点**由模型自行决定，不如云端引擎稳定。

## 设计上的取舍

- **不替你编内容。** 简历里没有的细节，模型被要求用占位提示而不是编造数字。
  这是刻意的约束——编错了在面试现场更致命。
- **「按住说话」不做二次确认。** 少点一下才是它的价值。需要审核就用输入框打字。
